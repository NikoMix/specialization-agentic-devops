## When to use this

Hypercare is the **post-go-live partner-on-standby phase**. The customer is operating the platform; the partner is paged only on Sev 1 / Sev 2 incidents or unblock requests. Hypercare exit triggers the final invoice.

## Inputs you need

- Signed KT plan (skills checks passed)
- Customer's incident severity rubric
- Baseline metrics from go-live (pipeline cycle time, GHAS open findings, Copilot adoption %)

## Step-by-step

The following sequence drives hypercare from go-live to exit.

<Steps>
1. Download the DOCX template.
2. Set the 30 / 60 / 90 day SLOs (see table below) and review with the customer.
3. Set up the weekly hypercare review meeting.
4. At day 30, day 60, day 90, score against SLOs.
5. At day 90, run the hypercare exit gate; transition to T&M or close the engagement.
</Steps>

## SLOs by phase

The SLO ladder tightens as the customer team gains independence.

| SLO | Day 30 | Day 60 | Day 90 |
|---|---|---|---|
| Partner response time (Sev 1) | 1h | 2h | 4h or T&M |
| Partner response time (Sev 2) | 4h | 8h | Next business day |
| Pipeline green-build rate | ≥ baseline | ≥ baseline + 5pp | ≥ baseline + 10pp |
| GHAS high-severity findings open &gt; 14 days | &lt; 10 | &lt; 5 | 0 |
| Copilot active-user rate | ≥ 40% of seats | ≥ 60% | ≥ 70% |
| Customer-resolved incidents (vs. partner-resolved) | ≥ 50% | ≥ 75% | ≥ 90% |

## Hypercare exit gate

The customer signs the exit gate when every row below is true.

- [ ] All Day 90 SLOs met or formally accepted with deviation notes
- [ ] No open Sev 1 / Sev 2 incidents
- [ ] Customer platform team self-reports confidence ≥ 4/5 per KT module
- [ ] Lessons-learned issue raised in this repo
- [ ] Final invoice raised

## Output: customer-ready deliverable

A signed hypercare plan + 30/60/90 scorecards + a signed exit gate.
