Module B is the part of the audit that is **specific to this specialization**. It is where most partners spend their preparation time, because the evidence cannot be reused from another specialization — it has to demonstrate real Agentic DevOps delivery on Azure and GitHub Enterprise Cloud.

| Control | Focus | Typical evidence |
|---|---|---|
| [1.1 Agentic DevOps Capability](/docs/module-b/1-1-agentic-devops-capability/) | Demonstrated technical capability | Case studies, architecture diagrams, capability statement, sample deliverables |
| [2.1 ACR Performance](/docs/module-b/2-1-acr-performance/) | Azure Consumed Revenue thresholds | Partner Center ACR exports, pillar breakdown, association evidence |
| [2.2 Customer Diversity](/docs/module-b/2-2-customer-diversity/) | ≥ 3 unique contributing customers | Customer list with DPOR / PAL / CSP association evidence |
| [3.1 Certifications](/docs/module-b/3-1-certifications/) | Certified individuals | AZ-400, GitHub Actions, GHAS and Copilot certification mapping |
| [4.1 Audit Readiness](/docs/module-b/4-1-audit-readiness/) | Submission quality | Evidence index, internal pre-audit review, submission package |
| [4.2 Partner Onboarding Assets](/docs/module-b/4-2-partner-onboarding/) | Repeatable delivery | Customer onboarding pack, HLD/LLD, KT plan, runbook, hypercare plan |

## Where the technical evidence comes from

Control B.1.1 is the heaviest lift: it requires architecture diagrams and case studies that name the specific GitHub and Azure services you delivered. The [Reference Architectures](/docs/engagement/reference-architectures/) page maps each of the six in-repo architectures to a published Microsoft Azure Architecture Center article you can cite and adapt, rather than drawing one from scratch.

Track collection status for all six on the [Evidence Tracker](/docs/evidence-tracker/).
